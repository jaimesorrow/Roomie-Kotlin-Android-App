# Release steps

1. Create separate Firebase staging and production projects. Enable Email/Password Auth and email-enumeration protection. Configure verification/reset email templates, budget alerts, and production Firestore. Use the Blaze plan required by deployed functions.
2. Register release `com.jaimesorrow.roomie` and debug `com.jaimesorrow.roomie.debug`. Add the matching downloaded config to `app/google-services.json`. It is ignored by git. Enable Play Integrity App Check for production and enroll the app-signing certificate. Register debug App Check tokens only in staging. Enable Firestore/Auth App Check enforcement after verifying legitimate requests; callable functions already enforce it.
3. Deploy the rules, indexes, and functions to the intended project explicitly:
   ```bash
   npm --prefix functions ci
   npx firebase deploy --project YOUR_PROJECT_ID --only firestore,functions
   ```
   Storage is unused and has deny-all rules; deploy its rules if you enable a bucket. Functions run in `us-west1`. The app uses the same region.
4. Enable Firestore TTL for `expiresAt` on `_deletions` and `reports`. Only completed deletion jobs have a TTL; pending jobs cannot expire before cleanup succeeds. The Auth-deletion trigger queues cleanup when an account is deleted outside the app. The worker is idempotent and retries failures. A complete job leaves a short-lived tombstone to prevent old sessions from recreating data. Add alerts for failing deletion and messaging triggers and the listing-expiry job.
5. Set up a staffed moderation process. Only service operators with a moderator custom claim can read reports; clients cannot moderate or write records. Inspect reports in the Firebase console. Remove abusive listings by setting `status: removed`; suspend accounts by setting `users/{uid}.status: suspended`. Resolve queued reports. Verify the housing/community terms and retention policy with the operator before release.
6. Review and complete the [privacy draft](privacy-policy-draft.md) and [account-deletion draft](account-deletion-draft.md), then publish pages with the operator's actual identity, contact, and retention details. The app implements deletion after password reauthentication. A public page must let someone request deletion without reinstalling the app; this requires an operator-run request channel.
7. Configure repository variables `PRIVACY_POLICY_URL`, `ACCOUNT_DELETION_URL`, `SUPPORT_EMAIL`, and secrets `GOOGLE_SERVICES_JSON_BASE64`, `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Use an upload key and Play App Signing; do not commit credentials.
8. Run the signed-release workflow from a verified commit. It produces an AAB and R8 mapping and does not publish to Play automatically. Increment the version code for later releases. Keep mappings for crash diagnosis.
9. On two staging accounts and a physical Android device, test signup, verification, reset, consent, publish/edit/close/renew, filters and pagination, interest, realtime messages, history, background notifications/denial/signout, both directions of block, reports, offline failures, account deletion, rotation/keyboard, TalkBack, and API 24/36 rendering. Firebase/FCM/App Check behavior cannot be proved by compilation or emulator rules alone.
10. Prepare store artwork, content rating, target audience, UGC declarations, app access/test credentials, Data Safety, privacy/deletion URLs, internal/closed testing, and the required Play Console release steps. Submit only after staging and signed-device tests pass.
11. Keep purchases disabled for the first staging validation. After the core marketplace passes, create the Play products described in [MONETIZATION.md](MONETIZATION.md), implement Google Play purchase-token verification and real-time developer notifications in Functions, and grant entitlements only from verified backend results. Do not use Play Billing for rent, deposits, or peer-to-peer payments.

[Android target requirements](https://developer.android.com/google/play/requirements/target-sdk) now specify API 36 for new mobile submissions. This project targets API 36. Payments are disabled in this MVP; the app never collects rent, and entitlement records are server-managed only.
